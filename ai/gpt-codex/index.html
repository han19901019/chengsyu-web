GPT + Codex 是什麼？
OpenAI 的新方向

Codex 被砍過、又復活、現在被縫進 GPT——它到底是什麼？OpenAI 想把它變成什麼？一篇看懂「寫程式代理」與「超級 App」的方向。

2026-07 更新 · OpenAI Codex × GPT-5.x

一句話：「Codex」現在不是一顆 AI 模型，而是 OpenAI 那個會自己寫程式的代理軟體——底層跑的是主力 GPT。OpenAI 正把「聊天 + 寫程式 + 上網」縫成一個超級 App。

Codex 的身世：被砍 → 復活 → 再收

Codex 這名字命運多舛，重點是它從「模型」變成了「代理」：

  • 2023
    初代 Codex 程式模型被下架，OpenAI 改用通用 GPT 處理寫程式。
  • 2025 / 5
    以 Codex-1（基於 o3）＋ Codex 代理軟體 復活。
  • 2026 / 2
    GPT-5.3-Codex＝最後一顆「獨立」的 Codex 模型。
  • 2026 / 3–4
    從 GPT-5.4 起，把 Codex 能力折進主力 GPT，不再有獨立的寫程式模型。
  • 現在
    「Codex」＝那個會自己寫程式、甚至能盯著你螢幕操作的常駐代理，模型底層是 GPT-5.x。

「超級 App」的終局：把三件事縫成一個

OpenAI 的大方向，是把三塊縫進同一個桌面入口：

  • ChatGPT——聊天、問答、寫作
  • Codex——會自己動手的寫程式代理
  • Atlas 瀏覽器——直接上網、操作網頁

聊天、寫程式、上網全在一個 App 裡完成——這就是所謂的「超級 App（super app）」策略：把越多事情收進同一個入口，越黏著、越難離開。

新戰場：agentic coding（會自己動手的 AI）

Codex 代表的是一個趨勢——AI 不只回答，而是自己動手做：開檔案、跑指令、改程式、反覆迭代，甚至常駐在你電腦裡幫你做事。這條路 OpenAI 用 Codex，Anthropic 用 Claude Code，兩家正面對決。

👉 差別主要在生態與調性：Claude 主打可靠、少 bug；Codex 走 OpenAI 生態、綁進超級 App。想深入比較，可看我們的 Claude vs GPT 選型。

實戰現場：成緒怎麼用 AI 代理

這些不是我們紙上談兵——成緒自己就是重度使用者。目前的架構是用 Claude（搭配 Claude Code）當大腦，一步步自建電商後勤系統：多通路對帳、庫存監控、客訴監控與每日自動化排程，都是用 AI 代理蓋出來、每天真的在跑；需要生圖與素材時，再交給 Gemini。

換句話說，我們把「會自己動手的 AI 代理」拿來解決電商營運的實際後勤，而不只是拿來聊天。這也是成緒的底氣——不是教你用 AI，而是每天用它把系統跑起來，再把這套經驗帶給品牌。

這對一般人與企業的意義

  • 好消息：不會寫程式，也能讓 AI 代理幫你把工具「做出來」，而不只是「教你怎麼做」——這正在快速降低導入自動化的門檻。
  • 要注意：「什麼都縫進一個 App」有取捨——越綁生態，選型自由越少。挑工具還是要看任務，別被單一入口綁死。
  • 務實觀點：AI 代理是趨勢，但真正的價值不在「用了哪個」，而在「用在對的地方」——把重複、耗人力的後勤先自動化，效益最直接。

常見問題

Q：Codex 是什麼？
OpenAI 那個會自己寫程式的代理軟體，底層是主力 GPT，已不是獨立模型。

Q：Codex 還是獨立模型嗎？
不是了，GPT-5.4 起折進主力 GPT；「Codex」現在指代理軟體。

Q：Codex 跟 Claude Code 差在哪？
都是 agentic coding 代理，差在生態與模型（Codex＝GPT／Claude Code＝Claude）。

AI 代理很強，但要用在對的地方

成緒行銷用「電商通路實戰 × AI」，幫品牌把對帳、庫存、客訴、報表等後勤自動化——後勤交給 AI，人才留給人。
